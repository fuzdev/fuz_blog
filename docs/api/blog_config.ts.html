blog_config.ts

The blogs registry, the consumer's src/routes/blogs.ts: each blog's BlogConfig, the registry's validation, and resolving a blog by its dirname. Free of node, gro, and Svelte imports, so gen, the tasks, and routes share it.

A single blog's configuration in the consumer's src/routes/blogs.ts registry.

dirname

Route directory under src/routes, and the blog's base path segment - so it equals the URL path, with no route groups or params, no leading or trailing slash, and no characters a URL would change (see validate_blog_configs). Post pathnames derive from it.

feed

Feed-level metadata. Post ids and urls and the feed's own URL derive from home_page_url, so set it to the blog's index page - its pathname must end with /<dirname>, after any deploy base path.

validate_blog_configs
#

blog_config.ts view source

(blogs: unknown[]): asserts blogs is BlogConfig[] import {validate_blog_configs} from '@fuzdev/fuz_blog/blog_config.js';

Validates the blogs registry, called by load_blogs_module so gro gen and the post tasks check it before touching any post file: each config is an object with only BlogConfig keys and a function or omitted scaffold, each dirname is a well-formed and unique string, each feed is a strict BlogFeedMetadata (so a leftover atom, now derived, fails), and each home_page_url has no query or fragment and a pathname (trailing slash ignored) ending with /<dirname>, optionally after a deploy base path (e.g. https://user.github.io/repo/blog). Post urls and the feed URL derive from home_page_url while the posts are routes under src/routes/<dirname>, so a mismatch would publish broken links.

blogs

the registry's blogs export, unvalidated
