type { title: string; date_published: string; date_modified: string; summary: string; tags?: string[] | undefined; } & Record<string, unknown>

The author-defined metadata for each post. Loose so a consumer can add its own fields (e.g. a devlog's series); the extras stay on the page's post and do not reach the generated BlogFeed (see resolve_blog_feed_item). The slug is not metadata - it comes from the post's <id>-<slug> directory name (see parse_blog_post_dirname).

import {BlogPostMetadata} from '@fuzdev/fuz_blog/blog.js';

resolve_blog_feed_item
#

blog.ts view source

resolve_blog_feed_item(post_dir: BlogPostDir, dirname: string, home_page_url: string, post: BlogPostMetadata): BlogFeedItem

Derives a BlogFeedItem (the feed entry) from a post, its directory's id and slug, and its blog's dirname and home_page_url. Emits only BlogFeedItem fields - a consumer's extra post metadata stays on the page's post for its component to render, and does not leak into the typed generated feed.

import {resolve_blog_feed_item} from '@fuzdev/fuz_blog/blog.js';

to_blog_feed_url
#

blog.ts view source

to_blog_feed_url(home_page_url: string): string

Derives a blog's Atom feed URL from its home_page_url. gro gen writes the feed to static/<dirname>/feed.xml, served beside the blog's index, so the URL is <home_page_url>/feed.xml (a trailing slash on home_page_url is ignored).

import {to_blog_feed_url} from '@fuzdev/fuz_blog/blog.js';
